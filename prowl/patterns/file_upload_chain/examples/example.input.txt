SaaS document collaboration platform — file attachment feature.

Upload endpoint: POST /api/v1/attachments
Observed request:
  Content-Type: multipart/form-data
  Body: file=<binary>, filename="report.pdf", content_type="application/pdf"

Server response (201 Created):
  {"attachment_id":"3f2a1b8c-9d4e-4f7a-b2c3-1a2b3c4d5e6f","url":"https://cdn.example.com/attachments/3f2a1b8c-9d4e-4f7a-b2c3-1a2b3c4d5e6f","expires_at":null}

Observed behavior:
- Server checks Content-Type header from request (mime_only); no server-side extension validation observed.
- Filename is preserved in a Content-Disposition header when served.
- Files stored on S3; served via CDN at cdn.example.com/attachments/{uuid}.
- Thumbnails generated asynchronously (observed thumbnail_url field populated ~2s after upload for image types).
- No expiry on attachment URLs — links are permanent.
- Attachments can be shared across team members; retrieval URL is not signed (no auth query param observed on CDN URLs).
- Platform also accepts .docx uploads; server renders a preview in the browser using an iframe pointed at the CDN URL.
- Observed a /api/v1/attachments/{id}/preview endpoint that proxies external URLs for "link preview" feature.
